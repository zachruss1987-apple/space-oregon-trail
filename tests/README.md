# Tests

Spec: `docs/process/testing.md`. Role brief: `docs/agents/tester.md`.

## Layout
```
tests/
  unit/<area>/<module>.test.ts   Vitest, node env (also src/**/*.test.ts)
  e2e/<flow>.spec.ts             Playwright, Chromium, vite preview of prod build
  e2e/helpers.ts                 gotoScene(), snap()
  e2e/seeds.ts                   known seeds (generated by scripts/find-seed.mjs)
  unit/spec/*.spec.test.ts       spec-driven tests derived from docs/design (not from the code)
  unit/spec/spec-helpers.ts      shared helpers (ship(), quietTick(), runTrials(), expectRate())
  unit/spec/find-seed.util.test.ts  seed finder, skipped unless FIND_SEED is set
```
Existing flat files (e.g. `unit/rng.test.ts`) move into `<area>/` as areas grow.

## Running
| Layer | Command |
|-------|---------|
| Types / lint | `npm run typecheck`, `npm run lint` |
| Unit | `npm test` (`SKIP_SLOW=1` skips statistical tests) |
| Unit + coverage | `npx vitest run --coverage` |
| E2E | `npm run test:e2e` (builds, serves on :4173) |
| Everything | `npm run test:all` |

## Determinism
- Sim code takes an `Rng` from `@/sim/rng`; tests use `createRng(<fixed seed>)`.
- Never use `Math.random` in sim or content.
- The game will read `?seed=<string|number>` from M1; e2e navigates via
  `gotoScene(page, key, seed)` so flows are reproducible. Until M1 the param is ignored.

## Scene contract (E2E)
- Each scene sets `document.body.dataset.scene` to its key in `create()`.
- `window.__PROXIMA__` exposes `{ game, version, state? }` (read-only snapshot).
- Wait on `data-scene`, never on timeouts. Prefer role/text locators; the canvas is opaque.

## Naming
- Unit: `tests/unit/<area>/<module>.test.ts`; name tests after design rules.
- E2E: `tests/e2e/<flow>.spec.ts` (e.g. `new-game.spec.ts`).
- One assertion idea per test; seed loops are fine for invariants.

## Speed budgets
Unit suite < 30 s (each test < 2 s), e2e < 3 min. Gate slow statistical tests
with `it.skipIf(process.env.SKIP_SLOW)`.

## Screenshots
```ts
import { gotoScene, snap } from './helpers';
await gotoScene(page, 'Boot');
await snap(page, 'Boot');          // -> test-results/screens/Boot.png
```
One screenshot per scene for designer review. No pixel assertions before M4 baselines.

## Spec tests (`tests/unit/spec/`)
One file per design doc, written from `docs/design` rather than from `src/`: `travel`, `repairs` (travel.md repairs, scan,
passing help), `health`, `events`, `hazards` (trail.md crossings), `store` (resources.md), `scoring`, `world`, plus
`invariants` (300-seed random-intent fuzz). Expected numbers are typed from the tables, so a failing spec test means the
code and the doc disagree: decide which is right from `docs/design/decisions.md`, then fix the code (bug card) or the doc.
Statistical rules use fixed seeds and `expectRate()` (4 binomial standard deviations); no test needs `SKIP_SLOW`.

## Finding seeds (e2e)
`node scripts/find-seed.mjs` runs `tests/unit/spec/find-seed.util.test.ts` under vitest with `FIND_SEED=1` (plain Node cannot
resolve the `@/` alias, so the search lives in a vitest file that is skipped otherwise). It plays the reference policy
(`runPolicy`) for the Executive, Window 3, over the string seeds `SEED-0`..`SEED-999`, prints the matches and rewrites
`tests/e2e/seeds.ts`. These are **policy-run seeds**: the UI turns `?seed=` into its Rng with the same
`seedFromString`, but a human's shopping and intents differ from the policy's, so use them as "likely" outcomes.

## E2E choreography helpers (`tests/e2e/helpers.ts`)
| Helper | Does |
|--------|------|
| `startRun(page, seed, snapSteps?)` | Title -> Setup (defaults) -> Store; optional per-step screenshots |
| `buy(page, row, qty)` | Store row number, type quantity, Enter (rows: 1 drives, 2 rations, 3 suits, 4 boxes, 5-7 parts) |
| `leaveStore(page)` | Row 8, confirm, farewell; ends on Travel |
| `autoTravelUntil(page, stop, opts?)` | Presses T on Travel and Enter on Waypoint/modals until `stop(state, scene)` or status leaves 'traveling'; skips input while `data-busy` |
| `pressUntilScene(page, scene)` | Enter until `data-scene` matches |
| `generousRun(page, seed)` | startRun + 4 drives, 3000 rations, 10 suits, 5 boxes, 1 of each part, leave to Travel |
| `reachWaypoint(page, wp)` | Auto-travel (threading hazards) to the Waypoint scene of waypoint `wp`; stops before pressing anything |
| `approachAndCross(page, row)` | At a hazard Waypoint: Enter (Hazard scene), then option key (1 thread, 2 shields, 3 tug, 4 pilot) |
| `sceneTexts(page, key)` | Text of every Phaser Text object in scene `key` (reads the scene graph; makes canvas copy assertable) |
| `settle(page)` | Wait out day animation and modals |
| `getState`, `sceneOf`, `idle`, `body` | Read `__PROXIMA__.state`, `data-scene`; wait out a day animation |
Notes: canvas text cannot be asserted (score table, rating), so assert `state` and screenshot. `seeds.ts` `ALL_ALIVE` is tried in order by
`journey.spec.ts`; UI arrival runs use `UI_ARRIVAL_SEEDS` in `journey.spec.ts` (SEED-9, SEED-20, SEED-8: 4 drives, 3000 rations, Half rations via `setHalfRations`, T auto-travel; verified by playing them, T-039 tuning), because the policy-run seeds rest and scan while the autopilot does not. `DEATHSEED` + 1 drive and no rations dies fast.
Screens: `screens.spec.ts` (all but Arrival) and `journey.spec.ts` (Arrival, Arrival-score) write to `test-results/screens/`.

M2 specs: `m2-economy` (Mars Relay sell/trade/talk/rest), `m2-crossing` (tug, shields, Belt pilot), `m2-route` (Titan direct route, Map, Heliopause after Kuiper), `m2-beacons` (epitaph survives a reload, shown on the Waypoint scene). Beacon lists are canvas-only: assert via `sceneTexts` and `localStorage['proxima.beacons']`.

## Visual regression (`tests/e2e/visual.spec.ts`)
One `toHaveScreenshot` baseline per scene (Title, Options, TopTen, Guide, Store, Travel, Supplies, Map, Hazard, Station, Death,
Arrival, Salvage-instructions, GfxPreview font page) with `maxDiffPixelRatio: 0.02`, `threshold: 0.3`. Determinism: fixed seed,
`?minigames=auto` (except the real Salvage screen), and `proxima.options` pre-seeded with reduced motion on, instant text, CRT off and
volumes 0 (so parallax, cursor blink, typewriter and the shader are off). Only the canvas is captured.
- Run: `npm run test:visual`. Update after an intentional visual change: `npm run test:visual:update`, review the PNG diffs, commit them.
- Baselines live in `tests/e2e/__screenshots__/<platform>/visual.spec.ts/<name>.png` (`snapshotPathTemplate` in `playwright.config.ts`).
  They are **platform-specific** (font and WebGL rasterization). Only `win32` baselines exist, so the spec is `test.skip`ped elsewhere.
  CI runs Linux Chromium: generate `linux` baselines (run the update script in the CI image and commit), then drop the skip. The PM decides CI handling.
- Any change to a scene's art or copy changes its baseline: re-run the update script as part of that card.

**Linux baselines (post-1.0 follow-up, card "CI: generate Linux visual baselines and enable visual suite in CI").** The visual suite is
`test.skip`ped off Windows, so CI (ubuntu) never runs it. To enable it: on Linux (or in the CI image / a `mcr.microsoft.com/playwright`
container matching the pinned Playwright version) run `npm run test:visual:update`; the PNGs land in
`tests/e2e/__screenshots__/linux/visual.spec.ts/`. Review and commit them, drop the `process.platform !== 'win32'` skip in
`tests/e2e/visual.spec.ts`, and add `npm run test:visual` to `.github/workflows/ci.yml`. Regenerate whenever art or copy changes.

## Audio e2e and bundle budget
`audio.spec.ts` asserts through `__PROXIMA__.audio` (`state`, `playing`, `volumes`). `tests/unit/spec/bundle.spec.test.ts` gzips `dist/assets/*.js`
and requires < 1.8 MB total; it is skipped when `dist/` does not exist (run `npm run build` first).
