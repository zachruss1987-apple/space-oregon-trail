# Tests

Spec: `docs/process/testing.md`. Role brief: `docs/agents/tester.md`.

## Layout
```
tests/
  unit/<area>/<module>.test.ts   Vitest, node env (also src/**/*.test.ts)
  e2e/<flow>.spec.ts             Playwright, Chromium, vite preview of prod build
  e2e/helpers.ts                 gotoScene(), snap()
  e2e/seeds.ts                   known seeds (generated by scripts/find-seed.mjs)
  unit/spec/*.spec.test.ts       spec-driven tests derived from docs/design (not from the code)
  unit/spec/spec-helpers.ts      shared helpers (ship(), quietTick(), runTrials(), expectRate())
  unit/spec/find-seed.util.test.ts  seed finder, skipped unless FIND_SEED is set
```
Existing flat files (e.g. `unit/rng.test.ts`) move into `<area>/` as areas grow.

## Running
| Layer | Command |
|-------|---------|
| Types / lint | `npm run typecheck`, `npm run lint` |
| Unit | `npm test` (`SKIP_SLOW=1` skips statistical tests) |
| Unit + coverage | `npx vitest run --coverage` |
| E2E | `npm run test:e2e` (builds, serves on :4173) |
| Everything | `npm run test:all` |

## Determinism
- Sim code takes an `Rng` from `@/sim/rng`; tests use `createRng(<fixed seed>)`.
- Never use `Math.random` in sim or content.
- The game will read `?seed=<string|number>` from M1; e2e navigates via
  `gotoScene(page, key, seed)` so flows are reproducible. Until M1 the param is ignored.

## Scene contract (E2E)
- Each scene sets `document.body.dataset.scene` to its key in `create()`.
- `window.__PROXIMA__` exposes `{ game, version, state? }` (read-only snapshot).
- Wait on `data-scene`, never on timeouts. Prefer role/text locators; the canvas is opaque.

## Naming
- Unit: `tests/unit/<area>/<module>.test.ts`; name tests after design rules.
- E2E: `tests/e2e/<flow>.spec.ts` (e.g. `new-game.spec.ts`).
- One assertion idea per test; seed loops are fine for invariants.

## Speed budgets
Unit suite < 30 s (each test < 2 s), e2e < 3 min. Gate slow statistical tests
with `it.skipIf(process.env.SKIP_SLOW)`.

## Screenshots
```ts
import { gotoScene, snap } from './helpers';
await gotoScene(page, 'Boot');
await snap(page, 'Boot');          // -> test-results/screens/Boot.png
```
One screenshot per scene for designer review. No pixel assertions before M4 baselines.

## Spec tests (`tests/unit/spec/`)
One file per design doc, written from `docs/design` rather than from `src/`: `travel`, `repairs` (travel.md repairs, scan,
passing help), `health`, `events`, `hazards` (trail.md crossings), `store` (resources.md), `scoring`, `world`, plus
`invariants` (300-seed random-intent fuzz). Expected numbers are typed from the tables, so a failing spec test means the
code and the doc disagree: decide which is right from `docs/design/decisions.md`, then fix the code (bug card) or the doc.
Statistical rules use fixed seeds and `expectRate()` (4 binomial standard deviations); no test needs `SKIP_SLOW`.

## Finding seeds (e2e)
`node scripts/find-seed.mjs` runs `tests/unit/spec/find-seed.util.test.ts` under vitest with `FIND_SEED=1` (plain Node cannot
resolve the `@/` alias, so the search lives in a vitest file that is skipped otherwise). It plays the reference policy
(`runPolicy`) for the Executive, Window 3, over the string seeds `SEED-0`..`SEED-999`, prints the matches and rewrites
`tests/e2e/seeds.ts`. These are **policy-run seeds**: the UI turns `?seed=` into its Rng with the same
`seedFromString`, but a human's shopping and intents differ from the policy's, so use them as "likely" outcomes.
