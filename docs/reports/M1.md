# M1 report — Core loop (2026-10-24)

## Shipped
A complete, winnable, losable run: Title → Setup (profession, 5 names, launch window) → Mattie's Outfitters → Travel loop (8 actions, auto-travel, supplies and map screens) → waypoints with M1 hazard roll → Death (with memorial beacon stored locally) or Arrival with score and rating. Keyboard-only play works; `?seed=` makes runs reproducible. Live on GitHub Pages.

## Architecture
- `src/sim` (18 modules, max 181 lines each): pure, immutable-state simulation; all randomness via one `Rng`; a second `Rng` for text variants so copy edits never change outcomes.
- `src/content`: design tables in TypeScript, player text in four JSON files with schemas; content tests enforce lengths, uniqueness, placeholders, and that every key the sim or UI can request exists.
- `src/ui` + `src/scenes` + `src/game/session.ts`: thin Phaser presentation; `data-scene`, `data-modal`, `data-busy` body attributes and `window.__PROXIMA__.state` form the test contract.

## Decisions and deviations
- Design numbers unchanged from the designer's M0 review; playthrough matched the design-side estimate within a few points.
- Station markups are placeholders until `economy.md` (M2 card T-046).
- `pixelArt` rendering disabled until the M4 pixel font so monospace text stays legible.
- Score bonus lines show even when zero (polish card T-049).

## Lessons
- Splitting text (writer) from rules (developer) by file, with placeholder JSON and a key contract, let three agents work the same feature concurrently with zero merge conflicts.
- Having the tester derive tests from the design docs rather than the code found no bugs this time but produced 446 tests that pin the spec; that is the regression net for M5 balancing.
- Agents must exclude `kanban/` from their commits (the PM edits it concurrently); all did after being told once.
- `npm run test:all` can fail on another agent's in-progress files; agents should scope their checks and report, not "fix" others' work.
