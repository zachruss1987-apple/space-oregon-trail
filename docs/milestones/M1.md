# M1 — Core loop

Goal: a complete, winnable, losable run from title to score screen, with text-first Phaser UI. The simulation is headless and exhaustively unit-tested; the UI is thin.

Design inputs: `docs/design/world.md`, `resources.md`, `trail.md`, `travel.md`, `events.md`, `health.md`, `scoring.md`, `ui.md`, `decisions.md`. Known: naive Farmer play wins ~1%; accepted for M1, balance target in M5.

## Sim (src/sim) — developer, tester
- `GameState` type and `createGame(options, rng)`: profession, crew names, launch window, supplies, credits, position, date, pace, rations, weather, event log.
- `tick(state, rng)`: advance one day. Distance by pace × drive health × weather. Consume rations. Update health score (rations, pace, weather, suits, illness). Roll daily events. Detect waypoint arrival. Detect deaths and game over (all crew dead, or no working drives and no repair).
- `store.ts`: buy/sell with price tables and per-station markup; validate limits and credits.
- `events.ts`: event table with weights, conditions, effects (see `docs/design/events.md`). Each event is a pure function on state.
- `health.ts`: illnesses with duration, death chance, rest-to-recover.
- `score.ts`: arrival scoring formula and rating title.
- `serialize.ts`: `toJSON`/`fromJSON` round-trip (needed for save/load later; cheap now).
- Balance smoke: a `tests/unit/sim/playthrough.test.ts` that auto-plays 200 seeded runs with the auto-play policy defined at the end of `docs/design/travel.md` and asserts win rate within a target band (e.g. 25–60%), average days 120–200, and no NaN/negative values.

## Content (src/content) — writer, designer
- `waypoints.ts`: 16 segments with names, distances, type (station/hazard/landmark), description text.
- `items.ts`: supplies with base prices, units, limits, weights.
- `events.json`: ≥ 25 events with text variants; ≥ 8 illnesses; death messages.
- `professions.ts`: 3 professions with credits, multiplier, perk text.
- `windows.ts`: 5 launch windows with weather profiles.
- `text/`: title screen copy, store dialog, status labels, epitaph templates.

## Scenes (src/scenes, src/ui) — developer
- `TitleScene`: title, menu (Travel the Trail, Learn about the Trail, See the Top Ten, Options placeholder).
- `SetupScene`: profession → crew names (5) → launch window.
- `StoreScene`: Mattie's Outfitters with quantities, running total, advice text.
- `TravelScene`: status panel (date, weather, health, thrust, rations, distance to next, credits), daily log, action menu with the eight canonical items from `docs/design/ui.md` (Continue on the Lane, Check supplies, Look at the map, Change thrust, Change rations, Rest, Attempt repair, Scan for salvage; the last auto-resolves per `travel.md` until M3).
- `EventScene` / modal: shows an event and choices.
- `WaypointScene`: arrival at a station/landmark with description; "Continue" or "Enter station" placeholder (full store in M2).
- `DeathScene` ("You have died of ..." + beacon epitaph entry stored locally) and `ArrivalScene` (score breakdown, rating).
- UI helpers: menu list with keyboard (arrows/enter/number keys) + mouse; text box with typewriter option; status bar.

## Tests — tester
- Unit: every sim module; property-style tests for invariants (supplies ≥ 0, health in range, date monotonic).
- E2E: full happy path with a fixed seed via `?seed=` query param: title → setup → store → travel until first waypoint → status checks. Death path with a seed known to kill the crew (seed discovered by a helper script and pinned).
- Visual: screenshot each scene at 640×400 into `test-results/` for the designer to review (not asserted pixel-perfect).

## Acceptance
- A human can play from title to arrival or death with keyboard only.
- `?seed=` makes runs reproducible; e2e uses it.
- Sim coverage ≥ 90%. All tests green in CI. Pages updated.
- Report in `docs/reports/M1.md` with win rate table from the playthrough test.
